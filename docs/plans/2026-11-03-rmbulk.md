# rmbulk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CSV / Excel に書いたチケット（最大30件程度、親子関係あり）を、確認画面を経て Redmine に一括登録する PowerShell 製 CLI `rmbulk` を作る。

**Architecture:** エントリポイント `rmbulk.ps1` が `lib/*.ps1` を dot-source し、サブコマンドを `lib/Commands.ps1` の関数に振り分ける。Redmine との通信はすべて `Invoke-RmApi` 1つを通し、単体テストではこれを Pester の Mock に差し替える。結合テストは Docker で起動した本物の Redmine に対して行う。

**Tech Stack:** Windows PowerShell 5.1 / PowerShell 7、Redmine REST API (JSON)、Excel COM、DPAPI（`ConvertFrom-SecureString`）、Pester 5 以降（このPCには 6.2.0 が両エディションに導入済み）、Docker（`redmine` 公式イメージ）

**Spec:** [docs/specs/2026-11-03-rmbulk-design.md](../specs/2026-11-03-rmbulk-design.md)

## Global Constraints

- PowerShell 5.1 と 7 の両方で動くこと。テストは両方で実行して両方 PASS させる。
- 実行時に追加モジュールを使わない（Pester は開発時のみ）。Excel は COM で読む。
- 認証は `X-Redmine-API-Key` ヘッダの API キーのみ。Basic 認証・プロキシ認証・証明書検証の回避は実装しない。
- 保存ファイルはツールのフォルダ直下: `config.json`（URL）、`apikey.dat`（DPAPI 暗号化）、`metadata.json`、`logs/`。すべて `.gitignore` 対象。
- API キーを平文でファイルやログに書かない。
- 入力の列名（完全一致、順不同）: `仮番号` `プロジェクト` `トラッカー` `題名` `説明` `開始日` `期日` `対象バージョン` `親チケット`。必須: `プロジェクト` `トラッカー` `題名` `開始日` `期日` `対象バージョン`。
- 確認プロンプトの文言: `登録しますか？(y/n)`。`y`（大文字小文字を区別しない）以外は登録しない。
- 集計の文言: `成功 {0}件 / エラー {1}件 / スキップ {2}件`。
- ログファイル名: `logs/rmbulk_yyyyMMdd_HHmmss.log`。
- ひな形の既定出力先: カレントディレクトリの `rmbulk_template.csv`（UTF-8 BOM 付き）。
- テキストファイルの書き出しは UTF-8 BOM 付き（5.1 と 7 で同じ結果にするため `[IO.File]::WriteAllText` + `New-Object Text.UTF8Encoding $true` を使う）。
- 関数名の接頭辞は `Rm`（例: `Invoke-RmApi`）。

## Review Focus

1. 説明に改行・カンマ・ダブルクォートを含む CSV（Excel で保存したもの）→ 1行のチケットとしてそのまま読める。テストは Task 4。
2. PowerShell 5.1 で日本語の題名・説明を送る → 文字化けせずに Redmine に届く（本文を UTF-8 のバイト列で送る）。テストは Task 2（単体）と Task 9（結合）。
3. Excel の数値セルに入った仮番号 `1` や親チケット `123`、文字列セルに入った日付 → `1.0` などにならず、手で書いた CSV と同じ値として扱われる。テストは Task 5。
4. 列名の行しかないファイル → `登録するチケットがありません。` と表示し、y/n を聞かずに終了する。テストは Task 8。
5. setup 後に API キーが無効になった、または Redmine に接続できない状態で import する → 確認の段階で原因（`rmbulk setup を実行し直してください。` を含む）を表示して終了し、登録は始まらない。テストは Task 2（401 の文言）と Task 8（import が止まること）。

## 共通データ構造

後続タスクが使う形をここで固定する。すべて `[pscustomobject]`。

**入力行（InputReader が返す）:** `RowNumber`([int]、ファイル上の行番号。列名の行が 1 なので最初のデータ行は 2)、`TempId` `Project` `Tracker` `Subject` `Description` `StartDate` `DueDate` `Version` `Parent`（すべて [string]。空セルは `''`。前後の空白は除去済み。Excel の日付セルは `yyyy-MM-dd` 文字列に変換済み）

**読み込み結果:** `@{ Rows = [object[]]; Warnings = [string[]] }`。必須列の不足・未対応の拡張子・ファイルなしは `throw`。

**メタデータ（metadata.json）:**
```json
{
  "fetchedAt": "2026-11-03T10:00:00",
  "projects": [ { "id": 1, "name": "WBS", "identifier": "wbs", "status": 1 } ],
  "projectDetails": {
    "1": { "fetchedAt": "...", "trackers": [ { "id": 2, "name": "タスク" } ],
           "versions": [ { "id": 5, "name": "v1.0", "status": "open" } ] }
  }
}
```
プロジェクトの `status`: 1 = 有効、5 = 終了（Redmine の値）。バージョンの `status`: `open` / `locked` / `closed`。

**チェック済み項目（Validator が返す Items の要素）:** `RowNumber` `TempId`([int] または $null) `ProjectId` `TrackerId` `VersionId` `Subject` `Description` `StartDate` `DueDate`（`yyyy-MM-dd`） `ParentIssueId`([int] または $null、既存チケット) `ParentTempId`([int] または $null、ファイル内)、表示用に `ProjectName` `TrackerName` `VersionName` `ParentText`（入力のまま）

**チェック結果:** `@{ Items = [object[]]; Errors = [object[]] }`。エラー要素は `@{ RowNumber=[int]; Kind='NotFound'|'Invalid'; Message=[string] }`。`Kind='NotFound'` はメタデータを取り直せば解消しうるもの（プロジェクト・tracker・バージョンが見つからない）。

**登録結果の要素:** `RowNumber` `TempId` `Subject` `Status`('Success'|'Error'|'Skipped') `IssueId`([int] または $null) `Message`

### Task 2: Redmine API

**Files:**
- Create: `lib/RedmineApi.ps1`、`tests/unit/RedmineApi.Tests.ps1`

**Interfaces:**
- Consumes: なし（接続情報は引数で受ける）
- Produces:
  - `Set-RmConnection -BaseUrl <string> -ApiKey <string>`（スクリプトスコープ `$script:RmConnection` に保持）
  - `Invoke-RmApi -Method <string> -Path <string> [-Body <hashtable>]` → 応答の JSON をパースしたオブジェクト。`-Path` は `/issues.json` のような先頭 `/` 付きのパスで、クエリ文字列を含んでよい
  - `Get-RmCurrentUser` → user オブジェクト
  - `Get-RmProjects` → `[object[]]`（`id` `name` `identifier` `status`）。`?limit=100&offset=n` で `total_count` に達するまで取得する
  - `Get-RmProjectTrackers -ProjectId <int>` → `[object[]]`（`id` `name`）
  - `Get-RmProjectVersions -ProjectId <int>` → `[object[]]`（`id` `name` `status`）
  - `Test-RmIssueExists -IssueId <int>` → [bool]（404 なら $false、それ以外のエラーは throw）
  - `New-RmIssue -Fields <hashtable>` → 作成されたチケットの id [int]。Fields のキーは API の項目名（`project_id` など）。値が $null または '' のキーは送らない

エラー時の throw メッセージ（`Invoke-RmApi` で統一）:
- 401: `認証に失敗しました（HTTP 401）。API キーが無効です。rmbulk setup を実行し直してください。`
- 422: `HTTP 422: ` + 応答の `errors` 配列を `; ` で連結したもの
- その他の HTTP エラー: `HTTP <code>: <応答本文または例外メッセージ>`
- 接続できない: `Redmine に接続できません: <例外メッセージ>`

例外から HTTP ステータスを取るには `$_.Exception.Response.StatusCode`、本文は `$_.ErrorDetails.Message` を使う（5.1 と 7 の両方で取れる）。

### Task 4: CSV の読み込み

**Files:**
- Create: `lib/InputReader.ps1`、`tests/unit/InputReader.Csv.Tests.ps1`

**Interfaces:**
- Produces:
  - `$script:RmColumns`: 列名 → プロパティ名の順序付きハッシュ（`仮番号`→`TempId`, `プロジェクト`→`Project`, `トラッカー`→`Tracker`, `題名`→`Subject`, `説明`→`Description`, `開始日`→`StartDate`, `期日`→`DueDate`, `対象バージョン`→`Version`, `親チケット`→`Parent`）と、必須列の配列 `$script:RmRequiredColumns`。Task 8 のひな形もこれを使う
  - `Read-RmInputFile -Path <string>` → 読み込み結果（共通データ構造）。拡張子で `Read-RmCsvTable` / `Read-RmExcelTable`（Task 5）を呼び分け、得た表を `ConvertTo-RmInputRows` に渡す
  - `Read-RmCsvTable -Path <string>` → `@{ Headers=[string[]]; Records=[object[]] }`（Records は列名をキーとするハッシュ、値は [string]）
  - `ConvertTo-RmInputRows -Headers <string[]> -Records <object[]>` → 読み込み結果。列名の前後の空白も除去する

例外メッセージ: 拡張子 `ファイル形式に対応していません（.csv / .xlsx / .xls のみ）: <path>`、必須列不足 `必須の列がありません: <列名をカンマ区切り>`。警告: `不明な列を無視します: <列名>`。

文字コード判別: 先頭が `EF BB BF` なら UTF-8。そうでなければ `New-Object Text.UTF8Encoding $false, $true`（不正なバイトで例外）で読んでみて、例外なら Shift-JIS（`[Text.Encoding]::GetEncoding(932)`）。文字列にしてから `ConvertFrom-Csv` に渡す。
