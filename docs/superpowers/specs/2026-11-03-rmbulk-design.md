# rmbulk 設計書

作成日: 2026-11-03

## 1. 目的と背景

WBS を引くたびに、Redmine のブラウザ画面でチケットを1件ずつ登録するのが手間になっている。
登録したいチケットを CSV / Excel にまとめ（AI に下書きさせることも想定）、コマンド1つで一括登録できるようにする。

- 1回の登録件数は最大30件程度を想定する。
- 当面の利用者は作者本人だけ。ただし将来チームに配る可能性があるため、他人の PC でも `setup` だけで使い始められる作りにする。

### 成功の姿

表を書いて `rmbulk import wbs.xlsx` を実行し、一覧を確認して `y` を押せば、親子関係も含めて WBS が Redmine に登録される。

### 非ゴール

- 既存チケットの更新・削除
- ステータス、担当者、優先度、カテゴリ、カスタムフィールドの指定（Redmine の初期値に任せる）
- Excel の複数シートの読み込み
- GUI

### アンチゴール（動いても失敗とみなすもの）

- 確認画面を通さずに登録される
- 確認の段階で分かるはずの入力ミス（名前の打ち間違い、日付の形式の誤りなど）が、登録の途中で初めて判明する
- API キーが平文でファイルに残る、またはツールのフォルダを渡すと漏れる

## 2. 制約

- Windows で動作すること。
- PowerShell 5.1 と PowerShell 7 の両方で動作すること。
- Excel 本体がインストールされている前提でよい（Excel ファイルは COM 経由で読み込む）。追加のモジュールは使わない。
- Redmine とは REST API（JSON）で通信し、認証には API キーを使う。
- 接続先の Redmine の画面は SSO で保護されているが、作者が試作した CLI では API キーだけで登録できた。そのため、REST API は SSO の対象外とみなし、API キー以外の認証（Basic 認証、SSO、プロキシ認証）や証明書検証の回避には対応しない。

## 3. コマンド構成

```
rmbulk setup                  # 接続設定とメタデータの取得
rmbulk refresh                # メタデータだけを取り直す
rmbulk template [<出力先>]    # 列名だけが入った CSV のひな形を出力する
rmbulk import <ファイル>      # CSV / Excel を読み込み、確認したうえで登録する
```

### 3.1 setup

1. Redmine の URL を入力させる（設定済みの場合は現在の値を初期値として表示する）。
2. API キーを入力させる。入力した文字は画面に表示しない（`Read-Host -AsSecureString`）。
3. `GET /users/current.json` で接続と認証を確認する。失敗した場合は理由を表示し、何も保存せずに終了する。
4. URL を設定ファイルに、API キーを DPAPI で暗号化したファイルに保存する。
5. メタデータを取得して保存する（3.2 と同じ処理）。

### 3.2 refresh

メタデータを取得し直して上書き保存する。保存済みのプロジェクト別の情報もすべて破棄する。

メタデータは2種類あり、取得するタイミングが異なる（私の判断。プロジェクトが多い環境で setup / refresh が遅くならないようにするため）。

| 内容 | API | 取得タイミング | 用途 |
|---|---|---|---|
| プロジェクト一覧 | `GET /projects.json`（ページング対応） | setup / refresh | プロジェクト名 → ID、プロジェクトの状態（終了しているか） |
| 各プロジェクトで使える tracker | `GET /projects/:id.json?include=trackers` | import で、そのプロジェクトが初めて使われたとき | tracker 名 → ID、およびそのプロジェクトで使えるかの確認 |
| 各プロジェクトの対象バージョン | `GET /projects/:id/versions.json` | 同上 | バージョン名 → ID（共有バージョンも含む） |

プロジェクト別の情報も、一度取得したら `metadata.json` に保存して次回以降に使う。

### 3.3 template

ひな形の CSV（UTF-8 BOM 付き、列名の行のみ）を出力する。出力先を省略した場合はカレントディレクトリの `rmbulk_template.csv`。

### 3.4 import

1. ファイルを読み込む（4章）。
2. 保存したメタデータで全行をチェックする（5章）。名前がメタデータに見つからない場合は、一度だけメタデータを自動で取り直してから再チェックする。
3. 一覧を表示する（6章）。エラーが1件でもあれば、エラー内容を表示して終了する（y/n は聞かない）。
4. `登録しますか？(y/n)` と聞く。`y` 以外なら何もせずに終了する。
5. 登録する（7章）。
6. `成功 ○件 / エラー ○件 / スキップ ○件` を表示し、ログファイルのパスを表示する。

## 4. 入力ファイル

### 4.1 形式

- 拡張子が `.csv` なら CSV、`.xlsx` / `.xls` なら Excel として読み込む。それ以外はエラー。
- 1行目は列名、2行目以降が1行1チケット。
- 全列が空の行は無視する。
- Excel は先頭のシートのみを読み込む。2枚目以降のシートは無視する。
- CSV の文字コードは、UTF-8（BOM の有無を問わない）と Shift-JIS を自動で判別する。

### 4.2 列

| 列名 | 必須 | 内容 |
|---|---|---|
| 仮番号 | 任意 | ファイル内で親を指定するための番号。正の整数。ファイル内で重複不可 |
| プロジェクト | 必須 | プロジェクト名、または識別子 |
| トラッカー | 必須 | tracker 名 |
| 題名 | 必須 | チケットの題名 |
| 説明 | 任意 | チケットの説明 |
| 開始日 | 必須 | `yyyy-MM-dd` または `yyyy/MM/dd`（Excel の日付セルも可） |
| 期日 | 必須 | 開始日と同じ形式。開始日以降であること |
| 対象バージョン | 必須 | バージョン名 |
| 親チケット | 任意 | 既存チケットの番号（例: `123`）、またはファイル内の仮番号（例: `#1`） |

- 列の順番は問わない。
- 必須の列がない場合はエラー。知らない列があれば警告を表示し、その列は無視する。
- セルの前後の空白は取り除く。

## 5. チェック内容（確認の段階）

行ごとに、次の内容をすべてチェックしてエラーを集める（最初のエラーで止めない）。

- 必須項目が空でないこと
- プロジェクトが存在すること（名前と識別子のどちらでも一致を探す。名前が複数のプロジェクトに一致した場合はエラーとし、識別子で書くよう促す）
- プロジェクトが終了していないこと（終了したプロジェクトにはチケットを登録できないため。私の判断）
- tracker がそのプロジェクトで使えること
- 対象バージョンがそのプロジェクトで使えること（ステータスが「終了」「ロック中」のバージョンはエラー）
- 開始日・期日が日付として解釈できること、期日が開始日以降であること
- 仮番号が正の整数で、重複していないこと
- 親チケット:
  - `#n` の場合: 仮番号 n の行がファイル内に存在すること。親子関係が循環していないこと
  - 数字の場合: `GET /issues/:id.json` でチケットが存在すること（メタデータではなく都度問い合わせる）
  - それ以外の書き方はエラー

確認の段階でチェックしないもの（私の判断）: 必須のカスタムフィールド、ワークフロー上の必須項目、チケット追加の権限。これらが原因の失敗は登録時のエラーとして扱い、Redmine が返したメッセージをログに残す。

## 6. 一覧表示

確認の段階で、全行を表形式で表示する。表示する列は次のとおり。

`行番号` `仮番号` `プロジェクト` `トラッカー` `題名` `開始日` `期日` `対象バージョン` `親チケット`

- 説明は長くなるため一覧には出さない。
- エラーがある行は、一覧の下に `行番号: エラー内容` の形でまとめて表示する。

## 7. 登録

- `POST /issues.json` で1件ずつ登録する。送る項目は `project_id`、`tracker_id`、`subject`、`description`、`start_date`、`due_date`、`fixed_version_id`、`parent_issue_id`。
- 親が先に登録されるように、ファイル内の親子関係で並べ替えてから登録する。親子関係のない行同士はファイルの順番を保つ。
- `#n` の親は、仮番号 n の行を登録したときに付いたチケット番号に置き換えて送る。
- ファイル内の親の登録に失敗した場合、その子孫の行は登録せず「スキップ」として扱う。
- 1件が失敗しても、残りの登録は続ける。
- 成功した行は、画面にチケット番号を表示する。

### 7.1 やり直し

やり直し用の機能は作らない。一部が失敗した場合、利用者がログを見て、失敗した行とスキップした行だけを残したファイルを手で作り、再実行する。成功した親を参照している `#n` は、利用者がログにあるチケット番号に書き換える。そのため、ログには行番号・仮番号・チケット番号の対応が分かるように出力すること。

## 8. ログ

- 実行ごとに `logs/rmbulk_yyyyMMdd_HHmmss.log` を作成する。
- 内容: 入力ファイルのパス、各行の結果（成功ならチケット番号、エラーなら Redmine から返ったエラーメッセージ、スキップなら理由）、最後に件数の集計。
- API キーはログに出さない。

## 9. 保存するファイル

ツールのフォルダの下に、次のファイルを置く。いずれも `.gitignore` に入れる。

```
rmbulk/
  config.json       # Redmine の URL
  apikey.dat        # DPAPI で暗号化した API キー（ConvertFrom-SecureString）
  metadata.json     # メタデータと取得日時
  logs/             # 実行ログ
```

`apikey.dat` は、保存した本人がそのPCでしか復号できない。そのため、ツールのフォルダごと他人に渡しても API キーは漏れない（受け取った人は自分で `setup` を実行する）。

設定をユーザーフォルダ（`%APPDATA%` など）ではなくツールのフォルダに置くのは、作者の希望による。ツールのフォルダを消せば何も残らないようにするため。チームで使う場合は、各自がツールのフォルダを自分の PC にコピーして使う前提とする（共有ドライブ上の1つのフォルダを全員で使う運用は想定しない）。

## 10. 実装者に任せること

- スクリプトの分割方法（1ファイルか、モジュール構成か）と、`rmbulk` コマンドとして呼び出す方法（`rmbulk.ps1` を直接実行するか、ラッパーの `.cmd` を用意するか）
- 一覧表示の見た目
- テストの方法（Redmine の API 呼び出しはモックに差し替えてテストできるようにすること）
- Excel の COM オブジェクトは、エラー時も含めて必ず解放し、Excel のプロセスを残さないこと
